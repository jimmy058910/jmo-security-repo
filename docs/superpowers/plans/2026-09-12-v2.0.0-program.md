# v2.0.0 program plan

> **For agentic workers:** this is a **program** plan, not a task plan. Phase 0 is
> written at task granularity because it runs against files that will not move
> before it executes. Phases 1–10 carry a roster, a "Measure first" block and an
> acceptance gate; each gets its **own** measured task plan when it starts — see
> [Why there are no task-level steps past Phase 0](#why-there-are-no-task-level-steps-past-phase-0).
> `scripts/dev/phase_audit.py` parses the rosters and the summary table; a roster
> line may contain **only issue numbers** (a PR cited as `#1213` once became a
> scheduled issue). Cite PRs by number without `#`, or by commit.

**Goal:** ship JMo Security v2.0.0 — 29 tools → 14 + a native pack, one
content-triggered matrix, one image, a shipped rule bundle, a SARIF importer, a
descriptor-table scan engine with honest per-tool accounting, and a clean repository —
with every open issue placed and every phase gated on a number through `jmo scan`.

**Architecture:** phases merge to `dev` as each lands (the v1.1.0 fix-program shape).
Order is forced by three dependencies: the cut precedes the descriptor table (18 blocks
to convert after it, measured 2026-09-24); the descriptor table precedes wiring new tools; the rule bundle
precedes semgrep's removal and osv-scanner precedes grype's verdict.

**Tech Stack:** Python 3.12, pytest (+xdist), uv / `uv.lock`, GitHub Actions, Docker
(WSL only on this machine), `gh` CLI, opengrep 1.30, zizmor 1.30.1, gitleaks 8.30.1,
osv-scanner 2.5.1.

**Spec:** [2026-09-12-v2.0.0-program-design.md](../specs/2026-09-12-v2.0.0-program-design.md).
The plan argues from the spec; read both. The SARIF importer has its own spec,
[2026-09-12-sarif-importer-design.md](../specs/2026-09-12-sarif-importer-design.md),
which is Phase 1.

## Global Constraints

Copied from the spec and the repository's rules; every phase's requirements implicitly
include these.

- **Backward compatibility is NOT a constraint.** There are no users. Profiles,
  Docker tags, fingerprints and `jmo.yml` keys change without deprecation.
- **One formatter:** `ruff format` (Black left with #1179). `make fmt && make lint &&
  make test` before every commit; `make` is **not on PATH** on this machine — run
  `pre-commit run --all-files` or the underlying commands.
- **No `shell=True`** in subprocess calls, ever.
- **Conventional commits. No AI-attribution markers of any kind** — not
  `Co-Authored-By: Claude`, not `Generated with Claude Code`, not a `Claude-Session:`
  trailer — in commit messages or PR bodies.
- **Never commit directly to `dev`.** Branch, PR into `dev`, squash.
- **Closing keywords go in an individual COMMIT message.** A PR body into `dev` is inert.
- **Gates are numbers through `jmo scan` / `jmo report`, never a bare binary.** Three
  recorded instances of a tool that worked standalone and produced 0 through `jmo.yml`.
- **Pre-dedup ≠ post-dedup.** Assert per-tool counts from per-tool runs; a combined run
  may cluster across tools and is not a stable assertion.
- **Verify every claimed issue's premise before building on it.** Five issue bodies in
  the last program carried a measured-false central claim.
- **Check line endings on every touched file**, not the expected ones: `git diff
  --numstat` vs `git diff --ignore-cr-at-eol --numstat`, **over the whole diff**, never
  a per-file `-- "$f"` loop, which cannot pair a rename and so misses a renamed file's
  flip (Phase 2: 575 phantom lines the loop reported as 0). The `mixed-line-ending`
  hook passes a wholesale CRLF conversion.
- **CI's only enforced coverage floor is 85%** (`coverage-aggregate`'s "Verify coverage
  threshold" step). Nothing sets `--cov-fail-under`; there is no local gate.
- **Run local suites with `PYTHONUTF8` unset.** CI pins it to `1`; no real Windows user
  has that.
- **Bound local runs:** `JMO_THREADS=2 .venv/Scripts/python.exe -m pytest tests/ -n 8 -q
  -m "not smoke and not requires_tools and not docker"`.
- **Read the `windows-2022` job log, never its check tick.** Diff the skip count too.
- **Check both CI events** (`push` and `pull_request`).
- **Mutation-test every guard.** Restore from a file backup, never `git checkout --`.
- **Long scans: detach via `Start-Process`.** The harness reaps a background shell after
  30 minutes without user input. Assert on `Wrote reports to`, never on rc.

## Why there are no task-level steps past Phase 0

`CLAUDE.md`: *"A plan written without running anything is a set of predictions, not a
spec."* Expanding ten phases into TDD tasks now would manufacture hundreds of unmeasured
predictions against a scan engine that Phase 2 deletes half of and Phase 3 restructures.
Each phase carries a **Measure first** block naming what to establish before its task
plan is written. That shape carried the v1.1.0 program through 14 phases.

## Ordering constraints (the load-bearing ones)

1. **Phase 0 precedes everything.** `origin/dev` is red, and the evidence every gate
   cites lives in a session scratchpad under `%TEMP%`.
2. **Phase 1 is independent of 2 and 3** and is already in flight (PR 1244, draft). It
   must land before Phase 4 wires its three tools.
3. **Phase 2 precedes Phase 3.** Cut first: the 18 `if` blocks it leaves become
   descriptors (11 of them in the repository scanner; measured 2026-09-24).
4. **Phase 3 precedes Phase 4.** New tools are descriptor rows, not new blocks.
5. **Phase 4 precedes Phase 6.** grype's verdict needs osv-scanner wired and re-measured.
6. **Phase 5 precedes Phase 7's measurement.** The memory target is of the final matrix
   with the merged bundle, not of semgrep.
7. **Phases 2 and 5 precede Phase 8.** Distribution assumes the Python tools are gone.
8. **Phase 9 (docs) then Phase 10 (release) are last.** Documentation describes
   behaviour; write it once behaviour is final.
