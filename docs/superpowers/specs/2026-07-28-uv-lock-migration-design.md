# Design: Migrate dev deps to PEP 735 `[dependency-groups]` + tracked `uv.lock`

**Date:** 2026-07-28
**Status:** Approved (design review passed; supersedes the open questions in `.claude/HANDOFF-uv-lock-migration.md`)
**Branch off:** `origin/main`, in a git worktree (primary checkout is shared with a peer agent — never stage/commit/checkout in it)

---

## Problem

Two independent defects share one root cause: dev dependencies have **two writers with different serializers**.

1. **Deps-compile drift.** `requirements-dev.txt` is generated by `uv pip compile --universal`, but Dependabot edits it directly with its own Linux-only pip resolver. Every Dependabot pip merge rewrites it into a non-canonical form; the next human PR fails the byte-equality `deps-compile` freshness gate with an unrelated-looking red. Happened twice on 2026-07-28 alone (PRs #677, #682, re-armed by #680). Not cosmetic: Dependabot's resolve drops platform-conditional deps (`pywin32==312 ; sys_platform == 'win32'` via `mcp`), silently breaking Windows dev installs.
2. **Dual declaration divergence.** Dev deps are declared twice: `[project.optional-dependencies] dev` (19 packages) and `requirements-dev.in` (30). The 19 are a strict subset — `pip install -e ".[dev]"` (the documented setup command) produces a smaller environment than CI uses. This class already caused PR #361 (missing `pytest-benchmark` broke a scheduled job).

The interim fallback considered in the handoff (drop pip *version* updates, keep *security* updates) does **not** fix the class: pip-ecosystem security PRs still rewrite `requirements-dev.txt` with the pip resolver. Only removing the file removes the second writer.

## Approved decisions

1. **Full migration** (not the interim fallback).
2. **Two PRs:** PR 1 = all functional changes + accuracy-critical doc lines; PR 2 = deep docs rewrite.
3. **Drop** the `[project.optional-dependencies] dev` extra (no alias — duplication is this bug's origin story).
4. **`astral-sh/setup-uv`** action (version-pinned) for CI, with built-in cache keyed on `uv.lock`.
5. **Lock-strictness asymmetry is deliberate:** CI and pre-commit use `--locked` / `uv lock --check` (hard-fail on stale lock); local `make deps-sync` uses plain `uv sync` (auto-refreshes the lock, change surfaces in `git diff`). Local hard-fail would add a manual step that protects nothing the CI gate doesn't already.

## Design

### 1. Single source of truth — `pyproject.toml`

- Add `[dependency-groups] dev` = the union of `requirements-dev.in`'s 30 entries, preserving their version floors. Do not enumerate here; read `requirements-dev.in` at implementation time.
- Delete `dev` from `[project.optional-dependencies]`. Keep the runtime extras (`reporting`, `email`, `mcp`, `attestation`, `visual`).
- Generate `uv.lock` with the pinned uv version and track it.
- Remove the `uv.lock` ignore block at `.gitignore:190-194`. The PR body must explicitly address the reversal: the block's premise ("CI uses pip-tools resolver") was already false (CI runs `uv pip compile`), "duplicates resolution" no longer applies once `requirements-dev.txt` is deleted, and the resolver-divergence argument is now inverted — this migration makes Dependabot and CI use the *same* resolver for the first time.

### 2. CI install pattern (~20 sites across ci.yml, scheduled.yml, maintenance.yml, release.yml + composite action)

Each `pip install -r requirements-dev.txt` site becomes:

```yaml
- uses: astral-sh/setup-uv@v7          # pin to current major at implementation time; uv itself pinned via the action's `version:` input
  with:
    version: "0.11.15"                 # single pinned uv across all sites (PR #488 convention)
    enable-cache: true
    cache-dependency-glob: "uv.lock"
- run: uv sync --locked --group dev
- run: echo "$PWD/.venv/bin" >> "$GITHUB_PATH"   # Windows: .venv/Scripts
```

- The `GITHUB_PATH` append keeps every existing `pytest`/`black`/`ruff` invocation unchanged — the migration stays mechanical, not behavioral.
- `uv sync` also installs the project itself (editable), which `pip install -r` never did — CI's env now matches the documented dev env exactly. If project install causes issues in any job, `--no-install-project` is the escape hatch.
- Update `.github/actions/setup-python-jmo/action.yml` to the same pattern (`cache-dependency-path` default moves from `requirements-dev.txt` to `uv.lock`; install step becomes `uv sync`).
- Keep a single pinned uv version across all sites (continuing the PR #488 convention; currently `0.11.15` — bump deliberately if setup-uv needs newer).

### 3. Gates replaced, not just deleted

| Old | New |
|---|---|
| `deps-compile` freshness gate (`ci.yml` ~70–89, byte-diff of regenerated `requirements-dev.txt`) | `uv lock --check` — semantic "is the lock consistent with the manifest?", resolver-symmetric so Dependabot PRs pass the same gate humans do. **Default: run unconditionally** (drop the event scoping — it existed only to excuse the second writer's format, which no longer exists). Deviate only if implementation surfaces a concrete reason. |
| `maintenance.yml` self-heal recompile (~line 174+) | Deleted; nothing left to heal. |
| pip-audit `-r requirements-dev.txt` (2 sites: `ci.yml:111`, `.pre-commit-config.yaml:172`) | `uv export --format requirements-txt --no-emit-project -o <temp>` then `pip-audit -r <temp>`. **Preserve both ignores**: `PYSEC-2025-183` (disputed pyjwt, transitive via mcp) and `GHSA-qp9x-wp8f-qgjj` (tuf<7 capped by sigstore, tracked #539). Wrap in `scripts/dev/audit_deps.sh` so CI and pre-commit share one implementation. Reword the inline comments that reference `requirements-dev.txt`. |
| `Validate requirements-dev.txt Python version` step (`ci.yml:65`, `update_dependencies.py --validate`) | **Default: retire the step** if its checks are subsumed by `uv lock --check` + `requires-python`; repoint at the new layout only if the script validates something the lock cannot. Decide in plan after reading the script. |
| `make deps-compile` / `deps-sync` / `deps-refresh` / `deps-validate` | `make deps-sync` (`uv sync --group dev`), `make deps-lock` (`uv lock`), `make deps-upgrade` (`uv lock --upgrade`). |

### 4. Dependabot config

`.github/dependabot.yml`: replace the `pip` ecosystem entry with `uv`. Same weekly Monday 09:00 schedule, same `python-minor-patch` group (minors/patches grouped, majors solo), same labels (`dependencies`, `python`), reviewer, and commit-message prefix. Security updates work natively.

### 5. Deletions

- `requirements-dev.in`, `requirements-dev.txt`
- The `deps-compile` pre-commit hook (`.pre-commit-config.yaml`) — replaced by a `uv lock --check` hook
- `.gitignore` uv.lock block (per §1)

### 6. PR split

- **PR 1 (functional):** everything above + accuracy-critical doc lines only — CLAUDE.md Development Setup (`pip install -e ".[dev]"` → `uv sync --group dev`), CONTRIBUTING.md setup commands. CI must be fully green on this PR alone.
- **PR 2 (docs):** `docs/internal/DEPENDENCY_MANAGEMENT.md` (33 refs — **rewrite**, not find-replace), `CONTRIBUTING.md` remainder (14), `docs/internal/PRE_COMMIT_HOOKS.md` (12), `docs/COMPLETENESS_ANALYZER.md` (6), 1-ref files (`TEST.md`, `docs/VERSION_MANAGEMENT.md`, `docs/TROUBLESHOOTING.md`, `docs/RELEASE.md`), `.claude/rules/release.rules.md` (replace the stale drift troubleshooting entry with a description of the old failure mode + how the migration removed it).
- **Local-only (no PR, must not be forgotten):** `.claude/skills/jmo-ci-debugger/*`, `.claude/skills/jmo-systematic-debugging/references/jmo-common-failure-modes.md`, `.claude/agents/{dependency-analyzer,release-readiness,security-auditor}.md`, `.claude/known-issues.md` — otherwise the CI-debugger skill keeps recommending the deleted `make deps-compile`.
- **Do NOT edit (historical records):** `CHANGELOG.md`, `docs/superpowers/plans/*` and `specs/*` (other than this file), `dev-only/archive/*`.

### 7. Out of scope

- Dockerfiles (verified: no `requirements-dev.txt` references in any of the 4 variants).
- npm ecosystems, docker/github-actions Dependabot entries — unchanged.
- Runtime dependency declarations (`[project] dependencies`, extras other than `dev`).

## Verification bar (all required before declaring done)

1. `uv sync --group dev` works on **Windows** and installs `pywin32` — the invariant the migration exists to protect. Verify explicitly.
2. Full CI green on PR 1, including all test shards (ubuntu ×4, macOS, Windows).
3. pip-audit still runs with both `--ignore-vuln` flags and still **fails on a real CVE** (temporarily pin a known-vulnerable dep, observe red, revert).
4. `quick-checks` passes on **both** `push` and `pull_request` events for the same commit (event-scoped logic is the only thing that can differ for an identical commit — this exact diagnostic isolated the original bug).
5. Post-merge: a Dependabot-style change introduces **no drift** on `main`.
