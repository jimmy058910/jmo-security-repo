# JMo Security v2.0.0 program — design

**Date:** 2026-09-12
**Status:** design approved in conversation; written spec awaiting review
**Sources:** the 2026-09-09 tool-matrix and execution review (A) and the 2026-09-11
coverage review (B), read **together** — B corrects A in two places (rule sourcing;
the opengrep taint gap) and revises A's matrix from 12 to 15 + a native pack. Both are
HTML under the gitignored `dev-only/audit/`; P0 copies them to
`C:\Projects\_archive\2026-09-12-jmo-v2-evidence\`. Every number this document depends
on is restated here so the spec stands without them. The SARIF importer design
(`docs/superpowers/specs/2026-09-12-sarif-importer-design.md`, PR #1244) is Phase 1 of
this program and is not repeated.

## 1. Problem

v1.1.1 advertises 29 tools. On Windows, 19 execute (measured 2026-09-09). A's ledger
classifies the 29 as 7 never installable here, 3 not applicable to a repository, 4
duplicates, 2 abandoned upstream, and one policy engine that is not a scanner; 11 of the
tools this program removes produce no output on a Windows repository scan, or none that
trivy had not already produced. Four profiles and four Docker images exist to subset those 29 by weight. SAST
rules are fetched live from Semgrep's registry on every scan, with telemetry forced on,
under a license that forbids distributing them, and 97% of what they report on the
target user's real applications is not a security finding.

Two reviews measured this (101 tool × target runs on 7 goat repositories and 2 real
applications; peak-memory sampling of every tool on a 4-file target) and reached a
verdict: prune and harden in place, not a rewrite. Neither review is tracked, no v2 scope
exists in any tracked document, `ROADMAP.md:19` still promises a patch cadence, and
`origin/dev` fails `phase_audit verify` with two unclaimed issues because the only plan
`phase_audit` knows is the v1.1.0 fix program.

This document is the v2.0.0 scope, its phase sequence, and the gate for each phase.

### 3.1 Profiles and images collapse

`fast/slim/balanced/deep` (9/13/17/29 tools) exist to subset by weight. With 14
content-triggered tools — all static binaries except checkov — and one merged rule file
per language the whole
matrix costs less than today's `fast` (105.6 s, 1,327 MB peak, 17 processes on
jmoadaptivegolf — A). A `deep` that equals `fast` is a lie, so `--profile` is removed —
not aliased; there are no users. The four `Dockerfile.*` encode the same coupling and
collapse to one `Dockerfile`; `release.yml` stops building eight images. Old GHCR tags
are not deleted, only no longer built.

## 5. The rule bundle (3′)

`jmo-rules/` is a **separable directory** shipped in the wheel and the image:

| Source | License | Languages | Freshness |
|---|---|---|---|
| opengrep/opengrep-rules `f1d2b56` | LGPL-2.1 + Commons Clause | 28 dirs; 2,086 rules, **1,593 `category: security`** (python 266, terraform 259, generic 248, javascript 169, java 116, ruby 90, go 71, yaml 69, php 61, csharp 48, scala 26, typescript 18, kotlin 14, c 12, rust 10, …) | frozen |
| GitLab `sast-rules`, `rules/lgpl-cc` | LGPL-2.1 + Commons Clause | java, javascript, php, python, ruby, yaml | maintained (v2.10.0) |
| 0xdea, elttam, dgryski | MIT | C/C++, misc, Go (stale 2024) | as-is |
| JMo pack | MIT OR Apache-2.0 | Next.js, Supabase, Firebase, browser LLM keys | ours; seeded from the scratchpad's `jmo-archetype-rules.yaml` (5/5 on fixture, 0/1,106 files on 3 real apps) |
| Trail of Bits | AGPL-3.0 | — | **excluded** |
| Semgrep registry | Semgrep Rules License v1.0 | — | **never fetched, never shipped** |

Rules are filtered to `metadata.category: security` (on the two real apps that removes
1,495 of 1,530 findings: `jsx-not-internationalized` 1,120, `react-props-spreading` 138 …
— B), deduplicated by `id` where GitLab and the snapshot overlap (GitLab wins; it is
maintained), and **merged to one YAML per language**. That merge is a 3.5× memory lever:
198 files = 1,874 MB / 27 processes; the same rules in one file = 535 MB / 5 processes,
identical 212 findings (A). Some snapshot directories fail opengrep's schema when passed
wholesale (`--config opengrep-rules` → rc 7, 0 scanned); the merge validates each rule.
Bundles are chosen by detected language and run offline; no scan makes a network call.

`THIRD_PARTY_LICENSES.md` at the repository root carries each source's notice.
`docs/RULE_BUNDLE.md` documents the swap path: replace the directory, keep the
per-language file names, run the fixture suite.

## 7. Plan mechanics

`scripts/dev/phase_audit.py:64-69` hardcodes `DEFAULT_PLAN` as the v1.1.0 fix program and
`ci.yml:1615-1620` runs `derive` and `verify` against it on every push. The v2 plan —
`docs/superpowers/plans/2026-09-12-v2.0.0-program.md` — replaces that constant in P0.
The v1.1.0 plan stays in place with a "superseded by" banner. The plan file follows the
parsed shape: `## Phase N — title` (`_PHASE_HEADING`, `:76`), a one-line
`**N issues:** #… #…` roster (`_ROSTER_MARKER`, `:86`), `## After the tag` (`:89`), and
the summary table with `| N — title | count |` rows and an `| after tag | N |` row.
Phase commit subjects keep the `Phase N — …` form `derive` matches.

The program plan carries rosters, gates and ordering only — the v1.1.0 plan's rule
("why there are no task-level steps here") holds. Each phase gets its own task-level
plan when it starts, written against the code as it is then, not as this document
predicts it will be.

**Measured 2026-09-12:** `phase_audit labels --apply` removes labels the plan does not
justify (`stale = have - {want}` → `--remove-label`), so the v1.1.0 `phase:N` labels go
in P0 without a separate step. **Still to verify in P0:** whether `.test_durations` has a
reader (two hits under `.github/`, none in `ci.yml` or `Makefile`).

clean-VM evidence in the PR body, per `CLAUDE.md`'s evidence gate.
